# 小程序优化清单

评估日期：2026-11-09  
状态：待实施

本清单基于当前小程序源码和现有自动检查整理。现有自动检查均通过；额外内存模拟复现了下述边界问题，没有操作实际用户记录。尚未完成手机真机体验验证。

## 一、优先修复：记录可靠性与准确性

### 1. 存储读取失败时保护原有数据

- [ ] 修复读取异常后创建空状态、再尝试写回的逻辑。
- [ ] 读取失败时保留原数据，向用户提示重试。
- [ ] 正常保存前保留可恢复副本。

**已确认的问题：** 如果本机存储读取失败、随后写入成功，空状态会覆盖原有数据。已用内存模拟复现。

**代码依据：** `miniprogram/utils/store.js` 中的 `loadState`。

**验收重点：** 模拟读取异常时不写回空状态；恢复读取后原记录仍可访问。

### 2. 跨天返回时刷新登记日期

- [ ] 每次返回“今日”页面时检查当前日期。
- [ ] 打开登记表单时再次检查日期。
- [ ] 跨午夜的草稿保留原日期，并提示用户选择登记日期。

**已确认的问题：** 日期只在页面首次加载时计算。跨天返回后，页面仍可能显示昨天，并继续编辑昨天的记录。已用内存模拟复现。

**代码依据：** `miniprogram/pages/today/index.js` 中的 `onLoad`、`onShow` 和 `startReflection`。

**验收重点：** 次日返回时正确显示当天；跨午夜的草稿不会丢失或静默记入错误日期。

### 3. 草稿恢复与误操作撤销

- [ ] 自动保存本机草稿，并与正式记录分开存储。
- [ ] 再次打开表单时支持恢复未保存内容。
- [ ] 增加明确的关闭按钮。
- [ ] 删除已有条目后支持撤销。

**已确认的问题：** 点击遮罩关闭表单，再次打开时会重新读取已保存记录，未保存输入会丢失。已用内存模拟复现。

**代码依据：** `miniprogram/pages/today/index.js` 中的 `startReflection`、`closeReflection`。

**验收重点：** 误关后可恢复草稿；草稿不计入正式结算，也不提前写入历史联想。

### 4. 统一满愿后的纠错规则

- [ ] 确定满愿后修改关联记录的业务规则，再实施调整。
- [ ] 保证满愿状态、累计数与详情说明一致。

**已确认的表现：** 目标为 3 功，达成后把当天记录改为 1 功，累计降为 1，仍显示已满愿。已用内存模拟复现。

**待决定的方案：**

1. 修改记录后重新计算满愿状态。
2. 冻结满愿时的结算数据，并清楚说明冻结后的纠错方式。

**代码依据：** `miniprogram/utils/store.js` 中的 `isVowComplete`、`syncVowCompletions`，以及今日登记保存逻辑。

**验收重点：** 不出现缺少解释的“累计低于目标但已满愿”；纠错结果符合选定规则。

## 二、完善长期使用体验

| 状态 | 优化方向 | 当前不足 | 建议 |

| 待实施 | 补记与纠错 | 功过簿只能查看历史日期 | 点击过去日期可补记；已有记录可编辑，并保留上一版供恢复 |

## 三、明确空白登记的含义

- [ ] 明确允许“今日已自省，无功过事项”的登记方式。
- [ ] 将“已自省但无事项”与“尚未登记”区分展示。
- [ ] 统一今日状态、日历明细和统计口径。

当前允许提交完全空白的登记。该行为是否保留属于产品规则选择，不直接视为缺陷；优化重点是让用户理解其含义。

## 四、建议实施顺序

1. 数据保护与跨天修复。
2. 草稿恢复。
3. 备份、补记与纠错；先明确满愿后的纠错规则。
4. 快捷录入和复盘统计。
5. 日历导航、计分说明、阅读与操作细节。
