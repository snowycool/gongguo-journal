# 功过格微信小程序导入与发布

## 工程定位

第一版是原生微信小程序，采用本机存储：

- 不需要后端或云开发；
- 不调用微信登录、手机号、定位、通讯录、相册等接口；
- 不上传功过、善愿或自省内容；
- 卸载小程序、清除缓存或更换设备后，记录可能无法恢复。

## 导入微信开发者工具

1. 登录微信公众平台，创建小程序并取得正式 AppID。
2. 打开项目根目录的 `project.config.json`，将 `appid` 替换为正式 AppID。
3. 在微信开发者工具中选择“导入项目”。
4. 项目目录选择 `gongguo-journal` 根目录，而不是单独选择 `miniprogram`。
5. 编译后检查“今日、功过簿、善愿”三个底部页面。
6. 使用真机预览，重点检查输入法弹起、弹窗滚动、底部安全区和本地保存。

## 发布前验证

- 首次启动没有演示记录。
- 空白功过数量为 0，填写内容后自动变为 1。
- 同一天再次登记会编辑并覆盖当天记录。
- 月历显示每天净数和本月净数。
- 全年视图显示 12 个月净数，点击月份可进入当月。
- 善愿按最新时间排序。
- 满愿卡片默认折叠、不可修改，并显示“圆”徽章。
- 满愿后自动弹出“立下一愿”。
- 满愿多出的净功自动顺延到下一愿；修改原记录后，满愿状态与后续善愿结余同步重算。
- 过数会从善愿累计中扣除，“距满愿还差”不出现负数。
- 善愿卡片以三列显示目标功数、累计功数和距满愿还差；累计功数以绿色突出，下方注明“功过相抵后计入善愿。”，不再单列累计过数。满愿详情第三列显示“满愿状态／圆满”。
- 清空本机记录必须二次确认。
- 断网状态下以上功能均可使用。

运行静态检查：

```powershell
node scripts/validate-miniprogram.js
node scripts/test-store.js
node scripts/test-share.js
```

## 分享功能与验证

### 实现范围

- 工程为微信原生小程序，`miniprogram/app.json` 首个注册页面和首个 tab 均为 `pages/today/index`。
- “今日”首页在原有 `Page` 中注册 `onShareAppMessage` 和 `onShareTimeline`，在原有 `onShow` 中调用 `wx.showShareMenu`，启用 `shareAppMessage`、`shareTimeline`。
- “功过簿”和“善愿”也可转发给好友或微信群，落地页始终为 `/pages/today/index`，不携带记录、统计或用户标识。
- 朋友圈接口不能自定义落地路径，只能分享当前页面。因此仅首页提供朋友圈分享；其他两个 tab 没有注册朋友圈回调，只开放好友/群转发。需要分享朋友圈时，先切换到“今日”。
- 分享标题固定为“极简功过格｜每日省察，修善断恶”。朋友圈显式设置 `query: ''`，不继承来源参数。
- 两种分享均显式使用代码包内 `/assets/share-cover.png`：复用已有静态“功”字图，防止好友分享默认截取当前页面而泄露个人内容。图片为 512×512 PNG；微信好友卡片按 5:4 展示，朋友圈按 1:1 展示，实际裁切需真机检查。
- `withShareTicket: false` 不影响普通微信群转发；本项目不读取群标识，不收集转发统计。
- 已检查 `app.json`、三个页面 JSON 和工程配置，原来没有分享配置或禁用调用；无需新增原生页面 JSON 的分享权限字段。分享入口由页面回调和菜单 API 配置。现有基础库配置为 `3.17.5`。
- 每页只有一次 `Page` 注册，保留原有 `onLoad`、`onShow` 内容；未修改存储、功过结算、登录或其他业务逻辑。

### 开发者工具复测

1. 导入项目根目录，编译“普通编译”，确认打开“今日”首页且控制台无新错误。选择基础库 `3.17.5` 或兼容的新版本；朋友圈回调和菜单参数至少要求基础库 `2.11.3`。
2. 打开首页右上角“…”；若模拟器支持对应入口，检查好友和朋友圈菜单。模拟器表现不能代替手机微信验证。
3. 可在 AppService 控制台检查首页回调（只检查返回值，不实际发送）：

   ```javascript
   getCurrentPages()[getCurrentPages().length - 1].onShareAppMessage({ from: 'menu' })
   // { title: '极简功过格｜每日省察，修善断恶', path: '/pages/today/index', imageUrl: '/assets/share-cover.png' }
   getCurrentPages()[getCurrentPages().length - 1].onShareTimeline()
   // { title: '极简功过格｜每日省察，修善断恶', query: '', imageUrl: '/assets/share-cover.png' }
   ```

4. 分别切换三个 tab，再回首页，检查菜单恢复；在自省表单、日期明细和善愿表单打开时检查好友分享返回值，仍只能包含上述固定标题、路径和图片。
5. 工具支持时使用“单页模式”调试：首页应可展示；自定义 tabBar 不渲染、立愿跳转和表单等能力受限，完整操作应通过微信底部“前往小程序”进入。
6. 运行 `node scripts/test-share.js`。该脚本只在 Node 内模拟微信 API 和存储，不访问真实微信数据；覆盖路由和图片存在、无隐私参数、单次页面注册、原有生命周期执行和重复显示时恢复菜单。

### 手机微信复测

1. 用管理员或有权限的测试微信扫码预览／体验版，在“今日”检查两个菜单；分别在可用的 Android、iOS 客户端检查，记录微信版本和基础库版本。
2. 在有权限的测试对象之间，从三个 tab 分别发送给好友、发送到测试群；用另一个账号点击卡片，确认进入“今日”首页，未收到发送者记录或善愿。首次使用者应无发送者数据，老用户只显示自己设备原有数据。
3. 检查分享面板及卡片标题与静态封面。在页面有记录、统计或已打开输入表单时再检查一次，不能出现发送者的文字、分数、善愿或页面截图。
4. 在首页发起朋友圈分享，检查标题和封面。用另一账号打开后，确认先进入首页的单页模式，再点击“前往小程序”，应进入完整首页。
5. 普通公众用户能否打开还取决于版本发布状态与访问权限；开发版／体验版测试成功不代表正式版已发布。正式版上线后还需用非项目成员微信复测好友、群聊及朋友圈访问。

### 平台限制与排查

- 个人主体身份不能由代码改变；本次只实现标准页面分享，不需要获取用户信息或群信息。未核验该 AppID 在公众平台的实际账号状态、类目、审核结果或分享能力限制，不能保证某个账号一定获准使用朋友圈能力。若代码正确但仍置灰，以公众平台通知和真机反馈为准。
- 腾讯官方当前公开类型定义仍将朋友圈标注为 Beta、基础库 `2.11.3` 起，并保留 Android 支持说明；不能据此承诺每个 iOS／微信版本均可用，也不在代码中按操作系统强行屏蔽。最终应以目标真机微信和最新平台实际开放情况为准。
- 首页不含 `web-view`、不要求微信登录，代码中没有隐藏首页分享菜单的调用；从朋友圈打开遵循单页模式，页面跳转、登录、表单等能力受微信限制，自定义 tabBar 不显示，本地存储与普通小程序模式隔离。
- 非首页朋友圈入口未启用是有意的范围限制，防止落地到功过簿或善愿页；不能通过在 `onShareTimeline` 返回 `path` 来解决。
- 不要把 `wx.showShareMenu` 调用成功、静态校验通过或模拟返回值通过视为真实发送成功。本次自动化检查没有向微信好友、微信群或朋友圈发送内容。

官方参考：[Page 分享回调](https://developers.weixin.qq.com/miniprogram/dev/reference/api/Page.html)、[显示分享菜单](https://developers.weixin.qq.com/miniprogram/dev/api/share/wx.showShareMenu.html)、[朋友圈与单页模式](https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/share-timeline.html)。本次官方文档站未能直接读取，参数和版本说明交叉核对了腾讯官方 [Page 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.page.d.ts) 与 [微信 API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。

## 隐私保护指引建议文案

> 功过格仅在当前设备本地保存用户主动填写的功过记录、善愿和自省内容，不将这些信息上传至服务器，不收集微信昵称、头像、手机号、位置、通讯录等个人信息。用户主动分享时，仅提供固定的公开标题、小程序首页入口与静态封面，不分享个人记录或统计。卸载小程序、清除缓存或更换设备后，本地记录可能无法恢复。

提交审核前，应在微信公众平台根据实际使用的接口重新核对隐私保护指引。如果后续增加登录、云同步、导出、个人内容分享或统计服务，需要同步更新隐私说明与授权流程。
